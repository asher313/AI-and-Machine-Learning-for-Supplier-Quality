# Evidence before operational use

The companion supplies teaching implementations and synthetic execution evidence.
An educational example can be complete for its stated lesson while remaining
unapproved for real decisions. Review the following evidence for the intended
data, users and consequences; this is not a universal compliance checklist.

| Build | Companion evidence | Acceptance evidence still needed for operational use |
|---|---|---|
| 1 Supplier risk | Reproducible fitting, temporal/maturity checks, monthly audit-policy metrics and a reserved-period protocol rehearsal | Representative source availability history; untouched post-selection evaluation; calibrated-risk evidence by relevant slice; monthly queue benefit relative to a baseline; human audit policy |
| 2 Defect prediction | Complete synthetic training/export/parity; a separate, failing predictive gate for the supplied negative example | Valid sensors and linked labels, including unmatched-cycle treatment; a frozen complete-cascade evaluation; prespecified hold burden and missed-defect limits; physical/quality-engineering approval |
| 3 NCR triage | Deterministic rules, schemas, review routing and scripted protocol replay | Adjudicated live-model evaluation, severe-error slices, automatically routed subset risk/coverage, reviewer error discovery, and separately measured touch time and elapsed time |
| 4 Standards assistant | Scoped retrieval contracts, deterministic refusal rendering, citation structure and scripted support checks | Licensed applicable source revisions; real retrieval recall; human-adjudicated support and relevance; malicious/stale-source tests and access checks on every retrieval path |
| 5 CAR drafting | Bounded workflow, scoped local checkpoint/resume and draft-revision review checks | Authenticated case-scoped review UI; approved multiworker storage; live draft quality; investigation evidence and engineering-approved verification plans; mature outcome follow-up |
| 6 Gateway | Text response contracts, configured routing, budget reservation, lifecycle events and teaching archive | All applicable call paths integrated; independent credential/egress enforcement; authoritative identity/classification; account-specific pricing; managed keys, retention, audit/charge reconciliation and incident drills |

For each operational system, name the accountable owner, approver, affected
decisions, permitted data/destinations, out-of-scope actions, fallback and
incident escalation. Record the model, prompt, corpus, source snapshot, policy,
configuration and dependency versions with the decision evidence. Monitor
infrastructure health separately from data quality, matured outcome quality,
human review, costs and business effects. Define recovery and retirement
conditions and actually test restoration and rollback.

Generated or model-selected text is not an authorization decision. Test
unauthorized source retrieval, forged or stale approval context, malicious
retrieved instructions, attempted effect replay, provider failures, incomplete
audit events and uncertain charges. Passing a finite test suite is not proof
that every attack or failure is covered.

The local SQLite workflow is not a distributed checkpoint service. The cloud
request generators do not provision a complete application. Joblib checksums
verify consistency, not trust in a downloaded artifact. The seven-year retention
example and `controlled` routing label are fictional policies, not legal advice
or authorization to process a particular category of information.
